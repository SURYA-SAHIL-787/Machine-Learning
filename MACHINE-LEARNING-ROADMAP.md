## 🧭 GUIDELINES — HOW TO USE THIS ROADMAP

1. **GO IN ORDER, PHASE BY PHASE.** DO NOT JUMP TO DEEP LEARNING OR LLMS BEFORE PHASE 1–2 ARE SOLID. WEAK FOUNDATIONS ARE THE #1 REASON LEARNERS GET STUCK IN PHASE 3.

2. **TREAT EACH TOPIC AS "LEARN → APPLY," NOT "READ → NEXT."** FOR EVERY BULLET, WRITE CODE THAT USES IT. READING ABOUT GRADIENT DESCENT IS NOT THE SAME AS IMPLEMENTING IT.

3. **DO NOT SKIP THE CHECKPOINTS.** IF YOU CANNOT DO THE CHECKPOINT TASK UNASSISTED, GO BACK — DO NOT MOVE TO THE NEXT PHASE ON HOPE.

4. **ONE PROJECT PER PHASE, MINIMUM.** PROJECTS ARE WHAT TURN "I WATCHED A COURSE" INTO "I CAN BUILD THIS." PUSH EVERY PROJECT TO GITHUB WITH A README EXPLAINING THE PROBLEM, APPROACH, AND RESULTS.

5. **REVISIT MATH AS NEEDED, NOT ALL AT ONCE.** YOU DON'T NEED TO MASTER ALL OF LINEAR ALGEBRA/CALCULUS BEFORE TOUCHING ML. LEARN THE MATH BEHIND AN ALGORITHM RIGHT BEFORE OR WHILE YOU IMPLEMENT IT — IT STICKS BETTER IN CONTEXT.

6. **PREFER OFFICIAL DOCS OVER RANDOM BLOG POSTS** FOR TOOLS AND LIBRARIES (SCIKIT-LEARN, PYTORCH, HUGGING FACE). BLOGS AND COURSES ARE GOOD FOR CONCEPTS; DOCS ARE GROUND TRUTH FOR SYNTAX AND BEHAVIOR.

7. **TRACK PROGRESS VISIBLY.** MAINTAIN A CHECKLIST (THIS FILE, A NOTION BOARD, A GITHUB PROJECT) AND MARK OFF SECTIONS AS YOU GENUINELY COMPLETE THEM — NOT AS YOU SKIM THEM.

8. **DON'T CHASE EVERY NEW TOOL.** ML/AI TOOLING CHANGES FAST. LEARN THE UNDERLYING CONCEPT (E.G. "EXPERIMENT TRACKING") DEEPLY WITH ONE TOOL (E.G. MLFLOW) — SWITCHING TOOLS LATER IS EASY IF THE CONCEPT IS SOLID.

9. **PHASE 4 IS A FORK, NOT A FINISH LINE.** PICK ONE SPECIALIZATION TRACK BASED ON THE JOBS YOU ACTUALLY WANT — DO NOT TRY TO GO DEEP ON ALL FIVE.

10. **REVISIT THIS FILE PERIODICALLY.** UPDATE IT AS TOOLS EVOLVE (E.G. NEW SERVING FRAMEWORKS, NEW LLM TECHNIQUES) SO IT STAYS YOUR LIVING SOURCE OF TRUTH, NOT A STATIC DOCUMENT YOU MADE ONCE AND FORGOT.
